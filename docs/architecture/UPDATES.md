Launcher executable: Tauri updater с собственным signing key; initial Windows installer дополнительно Authenticode. Backend хранит metadata/reference, private signing key ему недоступен. Не путать Tauri update signature и OS publisher certificate: они защищают разные этапы. При компрометации self-update key release freeze и out-of-band reinstall доверенного installer; in-band rotation через старый key подходит только при отсутствии компрометации.

Modpack: **The Update Framework (TUF)**, готовый Rust client (кандидат `tough`) и publisher tool, без собственного signature parser/crypto. Embedded root production, отдельный root staging. Root threshold 2-of-3 offline keys в отдельных защищённых хранилищах; targets подписываются offline release key, snapshot отдельным publisher key, timestamp отдельным online key. Обычный API/OWNER web session не получает targets/root keys. Корректное TUF refresh/version/expiration выполняет library, не ad-hoc manifest signature.

Project expiries: root 365 дней, targets 90 дней, snapshot 7 дней, timestamp 24 часа; timestamp обновляется только для существующего immutable release. Consistent snapshots включены; trusted metadata versions сохраняются локально. Refresh выполняется до install/update/PLAY; expired metadata не даёт запуск неподтверждённого текущего compatibility release. При временном hosting failure уже установленная сборка запускается только если local trust metadata ещё не expired, файлы проверены и backend/server доступны. Системный clock явно неверен → CLOCK_ERROR, expiry не отключается.

Root rotation проходит thresholds old/new roots по TUF. Потеря/компрометация threshold root = out-of-band recovery; «поставить новый key по API» не исправляет trust. Freeze/rollback/expired/mix-and-match failures видимы пользователю, нет fallback unsigned. Crypto/library maintenance и conformance проверяются на этапе 7 до production.

## Manifest как TUF target

Target `packs/stable/<release_sequence>/manifest.json`: UTF-8 JSON с schema_version=1,pack_id,channel,release_sequence,minecraft_version,loader{id,version},java{major,distribution_ref},minimum_launcher_version,integration_protocol_major,files[]. Exact file size/hash manifest в TUF targets metadata. Parser rejects duplicate JSON keys/unknown required schemas, body ≤2 MiB/files≤10000, total download initial cap 20 GiB configurable через trusted client policy.

File entry: portable relative path, SHA-256 lowercase, length bytes, side CLIENT/SERVER/BOTH, source reference, managed=true. Artifact URL не произвольный: source reference resolve только allowlisted HTTPS origins/known object keys. Target/channel/platform/version совпадают с authenticated compatibility response; backend compatibility не может подменить file trust. Launcher скачивает CLIENT/BOTH, server packaging — SERVER/BOTH. Server secrets/config credentials никогда не входят client manifest.

TUF target может быть самим артефактом или manifest, который фиксирует hashes внешних официальных artifacts. Legal redistribution проверяется отдельно: Minecraft assets/libraries/Java/mod files получают через разрешённые channels, не копируются автоматически в собственный CDN. Redirect только на allowlisted HTTPS origin; TLS verification обязательна. API URI не превращается в shell command.

Release sequence монотонен на channel/platform. Rollback продукта — новый больший sequence, ссылающийся на предыдущие проверенные bytes; metadata version не уменьшается. Actual backward-compatible game/world downgrade не автоматический: requires staging/save compatibility review и maintenance.

## Safe paths и владение файлами

Default install root — dedicated user-local AnimeOnCraft instance. User-selected root должен быть отдельным app-owned directory с marker; запрет filesystem root/system directory/существующего произвольного populated directory. Server manifest не выбирает абсолютный путь установки.

Manifest paths — ограниченный portable ASCII subset: no `..`,absolute/UNC/drive,backslash,colon/ADS,NUL,Windows reserved names,trailing dots/spaces,case-insensitive duplicates. На каждом traversal проверять reparse points/symlinks/junctions и final containment; простого string prefix недостаточно. Refuse их внутри managed tree; handles/no-follow checks предотвращают TOCTOU. Archives на MVP не извлекаются из arbitrary download: files доставляются отдельно; если library/Java архив нужен, он проходит отдельный checked extraction с теми же bounds.

Manifest не управляет saves/screenshots/logs/options/keyring/cache/staging/journal. Mutable config overrides проектируются на этапе 9: managed baseline и user settings разделены явным catalog, незнакомый config не перезаписывается молча. Untracked jar в mods не удаляется автоматически и не считается trusted: launch блокируется с явной repair/quarantine операцией.

## Install/update/repair transaction

Один native instance lock исключает конкурентные install/repair/PLAY. Game running блокирует обновление managed game tree. Сравнить approved manifest с local managed index, потоково hash managed files; только missing/changed/corrupt скачиваются. Limited 4 downloads, size/time/cancel bounds, disk free precheck для staging+rollback copies. Cache content-addressed по hash; cached bytes перепроверяются перед promotion, corrupt cache удаляется в пределах owned cache.

Загрузка в owned staging `.part`, verify length+SHA-256 до commit. HTTP Range resume допускается только при validated server response/ETag и final full-file hash; mismatch restart, не success. Progress byte-based, отдельные phases download/verify/apply, ошибки реальные.

Per-file atomic replace не делает всю сборку атомарной. Поэтому persisted journal: prepare список managed paths и rollback copies → apply verified files → validate managed index → commit marker/manifest atomic rename. Crash recovery перед PLAY заканчивает transaction либо возвращает предыдущий согласованный managed набор. Dirty journal никогда не запускается. Stage/rollback dirs на том же volume, fsync/write durability учесть для Windows. Старые managed файлы удаляются только по index этого instance; не весь installation root.

Repair сверяет approved manifest и восстанавливает повреждения. Reinstall заменяет только managed catalog; userdata сохраняется и предварительно копируется при миграции. Cache clear только cache. Full userdata reset — отдельная явно destructive операция, не часть routine reinstall. Rust capabilities не принимают произвольный delete path от UI.

## Native launch и settings

RAM bounds по available memory, Java executable canonical local path и validated runtime version, resolution positive/bounded, fullscreen boolean. Native запускает executable+argv без shell. JVM args allowlist для memory/GC/safe properties; запрет `-javaagent`,agentpath/agentlib,bootclasspath и unsafe arbitrary executables. Expert extensions требуют отдельной explicit setting и review, не remote manifest.

Launch adapter использует проверенную library/metadata выбранного loader и official Minecraft auth. Vanilla CLI access token может оказаться видимым same-user process observer: это остаточный риск trusted local OS; argv/log output redacted, не сохранять token в запускном скрипте. AnimeOnCraft bearer не передавать Java process вообще. Native emits bounded process logs, exit status; PLAY disabled при pending application/identity requirement/denied access/dirty install/unsupported runtime.

Launch feasibility spike должен доказать Windows build, permitted auth client ID, official profile/ownership, loader metadata/dependencies/native libs/gameDir и process start. До этапов 8–10 реальный PLAY не объявляется готовым; update testing uses явно test-only artifacts.
